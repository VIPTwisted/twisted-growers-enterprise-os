A ZERO FROM THIS CONNECTION MAY MEAN "NOT ALLOWED", NOT "NOT THERE".
=========================================================================
You read the database as the role tg_desktop_reader. Row-level security is ON
for most tables here, and almost every policy is written `to authenticated`.
That role is NOT authenticated, so where no policy matches, Postgres returns
ZERO ROWS WITH NO ERROR. Not a permission message - an empty result that looks
exactly like an empty table.

Proved 8 Aug 2026: asked how many documents exist, this connection answered
"metrc_documents itself has 0 rows". It holds 3,675.

SO: BEFORE YOU REPORT THAT ANYTHING IS EMPTY, MISSING OR NOT TRACKED, check
whether you can see the table at all:

  select relname, relrowsecurity from pg_class
   where relname = 'the_table';                      -- RLS on?
  select count(*) from pg_policy p join pg_class c on c.oid = p.polrelid
   where c.relname = 'the_table'
     and 'tg_desktop_reader' = any(select rolname from pg_roles
                                    where oid = any(p.polroles));

If RLS is on and no policy names your role, SAY SO. Report it as "I cannot see
this table from the desktop connection", never as "there is no data". The
difference sends somebody hunting a problem that does not exist while hiding
one that does, and it is the exact error the rule above this one forbids.
