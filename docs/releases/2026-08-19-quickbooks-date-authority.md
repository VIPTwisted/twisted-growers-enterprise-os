# QuickBooks Date Authority — 19 August 2026

## Released contract

- Supabase is the only executable date-preset authority. `f_date_presets` serves
  all 27 configured choices with resolved endpoints, Monday-based weeks, fiscal
  periods, rolling windows, and open-ended manual modes.
- `f_date_default` now honours, in order: a user's saved range on this page, the
  user's everywhere default, `nav_registry.default_range`, then Today for a
  snapshot or This Month for activity.
- Date-aware pages wait for the governed default before reading data. Failure is
  visible and no all-time population is substituted.
- The shared selector defaults otherwise-unclassified date surfaces to This
  Month, supports saving this page or all pages, and swaps reversed custom dates.
- An inclusive To date is implemented as `< next day`, so a timestamp at any
  time on the selected final day remains inside the population.
- Command, Cultivation, Inventory, Harvests, Harvest Lifecycle, Loss Ledger, the
  generic report engine, generic department dashboards, and Schedule Adherence
  now bind the displayed range to their reads. Schedule's KPI and drill ranges
  are one mechanism; its former second Month/Quarter/Year KPI control is gone.

## Deployment safety

The migration returns both `preset_key` and `governed_preset_key` temporarily.
The old production browser receives `custom` plus exact endpoints for preset
keys it does not understand; this release reads the real governed key. Remove
the bridge only after the new browser is the sole production client.

## Verification

- Anchored database checks prove This Week = Monday–Sunday, MTD ends on the
  anchor, rolling 90 includes exactly 90 days, and Last YTD preserves the prior
  year's comparable day.
- Anonymous preset access is denied; authenticated users have SELECT/EXECUTE but
  no preset-table write grant.
- `f_schedule_cost_range` recomputes schedule cost figures from the same detail
  rows the tile drills open.
- Unit tests cover rollover, leap day, reversed ranges, catalogue validation,
  governed-key compatibility, RPC errors, and page/everywhere saves.

## Open work — do not describe this slice as the entire date program

- Prior-period and prior-year comparison columns/charts are not yet a shared
  contract. They should be generated by a database comparison function, not
  inferred independently by each chart.
- Some older special pages still load a bounded all-record source and then apply
  the shared month filter in memory. Their visible population is correct, but
  they should be migrated to server-side range predicates in subsequent small
  releases.
- Empty generic objects still infer their date capability from returned values.
  The report registry/schema should be the authority so an empty but date-capable
  table retains its date control.
- The existing Supabase advisor backlog (security-definer views, mutable search
  paths, and duplicate/permissive policies) predates this release. The three new
  functions are SECURITY INVOKER with pinned search paths and explicit grants;
  this release does not silently broaden itself into that separate remediation.
